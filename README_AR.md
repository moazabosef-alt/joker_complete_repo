# متجر الجوكر — Flutter Android + Web + Supabase

هذه حزمة **كود مصدر قابل للتطوير**. تشمل واجهة الزبائن، منتجات وصور ومخزون، سلة وطلبات آمنة عبر RPC، إعجابات وعداد، تقييمات واقتراحات، روابط منصات، لوحة المدير والموظفين، سياسات صلاحيات قاعدة البيانات، وبناء Android وWeb عبر GitHub Actions.

**الحالة بوضوح:** لم يُبنَ APK أو موقع منشور، ولم يتم تشغيل Flutter Analyzer في هذه البيئة (Flutter SDK غير مثبت). يجب البناء والاختبار قبل النشر. إدارة إنشاء الموظفين وتعديل صلاحياتهم **ليست واجهة مكتملة داخل التطبيق**؛ يتم ذلك في Supabase بواسطة المدير حاليًا. حماية الإعجابات والتقييمات من الإساءة تحتاج بوابة rate limiting / CAPTCHA قبل إطلاق عام. هذا ليس ضمانًا أن جميع الميزات جاهزة للإنتاج.

## 1) ارفع المستودع

أنشئ مستودع GitHub جديدًا باسم `al-joker-store` وارفع **محتويات هذا المجلد** إلى جذر المستودع، وليس ملف ZIP وحده. من الهاتف: GitHub > New repository > Add file > Upload files (قد تحتاج وضع سطح المكتب أو حاسوب لرفع مجلدات كثيرة). أسهل طريقة باستخدام حاسوب Git: `git init`, `git add .`, `git commit -m "Initial Joker store"`, `git branch -M main`, `git remote add origin https://github.com/USERNAME/al-joker-store.git`, `git push -u origin main`.

## 2) Supabase — مهم جدًا

- **إذا تستخدم مشروع Supabase السابق الذي فيه بيانات:** لا تشغل `supabase/schema.sql` من البداية بشكل أعمى. احفظ نسخة احتياطية، راجع اختلافات الجداول وسياسات RLS. كانت بنية GitHub السابقة مطابقة للملف الأساسي في هذا المشروع، لكن قد تكون قاعدة بياناتك الفعلية مختلفة.
- **إذا تستخدم مشروع Supabase جديدًا وفارغًا:** شغّل `supabase/schema.sql` في SQL Editor، ثم أنشئ مستخدم المدير عبر Authentication > Users، وأضف معرفه **مرة واحدة فقط** إلى `public.admin_users` من SQL Editor باستخدام معرف المستخدم الصحيح.
- بعد ذلك شغّل بالترتيب `supabase/migrations/20261114_staff_permissions.sql` ثم `20261114_staff_login_rate_limit.sql` ثم `20261115_feedback_social.sql`.
- يجب أن يبقى `admin_users` محتويًا على **حساب المدير الرئيسي فقط**. لا تضف الموظفين إليه.
- لا تشارك `service_role` أو كلمات مرور الموظفين ولا تضعها في GitHub أو Flutter أو Actions.

## 3) إعداد الموظفين

تحتاج 10 حسابات في Authentication > Users مع بريد داخلي فريد لكل موظف. شغّل قالب `supabase/PROVISION_ONE_EMPLOYEE.sql` بعد تعديل القيم لكل موظف. موظف يسجل الدخول باسم مستخدم وكلمة مرور عبر Edge Function `staff-login`؛ المدير يسجل بالبريد الإلكتروني وكلمة المرور. انشر Edge Function باستخدام Supabase CLI أو Dashboard. راجع `supabase/STAFF_SETUP_AR.md` قبل النشر، وفعّل حد محاولات الدخول وحماية على البوابة. يمكن إدارة صلاحيات الموظفين من Supabase SQL Editor؛ لم نضمّن بعد واجهة آمنة لإنشاء الحسابات من التطبيق.

## 4) GitHub Actions

Settings > Secrets and variables > Actions > New repository secret:

- `SUPABASE_URL`: رابط المشروع العام.
- `SUPABASE_PUBLISHABLE_KEY`: المفتاح العام publishable/anon فقط.

Actions > Build Android and Web > Run workflow. ستظهر مخرجات `joker-android-apk` و`joker-web-site` في Artifacts إذا نجح البناء. **مخرجات Web ليست رابطًا منشورًا**؛ انشر `build/web` على استضافة HTTPS مثل Cloudflare Pages أو Firebase Hosting. لن يعمل الموقع بمجرد رفع المصدر إلى GitHub.

> مفاتيح `--dart-define` ليست أسرارًا مخفية في APK/Web. استخدم المفتاح العام فقط، واعتمد على RLS لحماية البيانات.

## 5) ما يعمل في الواجهات / ما يحتاج إكمالًا

- موجود في الكود: كتالوج، بحث، أقسام، سلة، طلب داخل المتجر، صور المنتجات، تسجيل دخول، لوحة منتجات وطلبات، اقتراحات، إعجابات، روابط المنصات.
- **محدود**: تعديل منتج في واجهة الإدارة يرسل جميع الحقول؛ الموظف الذي يمتلك صلاحية تغيير السعر فقط قد يحتاج واجهة تحرير مخصصة لا ترسل الحقول الأخرى عند تعديلها. RLS/trigger يمنع التغييرات غير المصرح بها.
- **غير مكتمل**: إنشاء حساب موظف وتعديل صلاحياته داخل التطبيق، إضافة أقسام من الواجهة، عرض متوسط تقييم إجمالي في واجهة الزبائن، الدفع الإلكتروني، تنبيهات الإصدارات، وتهيئة PWA بأيقونات وهوية مخصصة. يمكن إضافتها لاحقًا.
- **يجب اختباره**: تسجيل الدخول باسم المستخدم (يعتمد على شكل استجابة Edge Function)، رفع الصور على Android/Web، تزامن عداد الإعجابات، حماية المعدل، والأذونات بعد إنشاء حسابات الموظفين.

## 6) للتطوير لاحقًا

قسمنا وظائف Supabase إلى مخطط أساسي وترحيلات مستقلة. أضف أي ميزة جديدة في ملف ترحيل SQL جديد مع واجهة Flutter مستقلة، ولا تحذف بيانات الجداول الموجودة. يفضل مستقبلاً تقسيم `lib/main.dart` إلى ملفات `features/` و`services/` و`models/`، وإضافة اختبارات آلية وCI صارم قبل النشر.
